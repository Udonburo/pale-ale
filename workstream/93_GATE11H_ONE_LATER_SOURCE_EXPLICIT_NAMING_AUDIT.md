## 4. Later-Source Explicit-Naming Discipline

Gate11H must audit naming existence, not later-source admissibility itself.

One later-source naming instance counts only if all of the following are true:

- an explicit later-source marker is present
- exactly one later source is named
- the full Gate11E path is explicitly attached to that same later source
- no shortcut or worker-side synthesis is required

If any of those conditions is absent, Gate11H must not promote the line into one explicit later-source naming.

## 5. Required Naming Conditions

### 5.1 Explicit Later-Source Marker Is Present

One later-source naming instance counts only if:

- the controlling source explicitly provides one `later_source_id` or `later_frozen_run_id`

Narrative wish or generic future-language does not count.

### 5.2 Later-Source Cardinality Is Single

One later-source naming instance counts only if:

- exactly one later source is named
- no second competing later source is implicitly or explicitly introduced

Multiple later sources must be treated as:

- `deferred`

### 5.3 Full-Path Attachment Is Explicit On That Same Later Source

One later-source naming instance counts only if the controlling source explicitly states that the same later source carries:

- one declaration marker
- one candidate id
- one class
- one explicit host-failure sentence
- matched status, registry, and read surfaces

If those elements are not explicit on the same later source, one later-source naming is not yet established.

### 5.4 Anti-Shortcut Boundary Remains Intact

One later-source naming instance counts only if:

- broader-settlement promotion is not needed
- retroactive rewrite is not needed
- graph-wide leap is not needed
- worker-side synthesis is not needed
