## 4. Instantiation-Path Discipline

Gate11I must define path conditions, not later-source admissibility itself.

One later-source explicit-naming instance counts as later honestly instantiable only if all of the following are fixed:

- the missing naming components are named explicitly
- one later source and only one later source is added in one later source
- the full Gate11E path is attached explicitly on that same later source
- no shortcut or worker-side synthesis is required

If those conditions are not fixed, Gate11I must not promote the line into instantiation-path definition.

## 5. Required Path Conditions

### 5.1 Missing Naming Components Are Explicitly Named

The path counts as defined only if the minimum missing components are named explicitly.

Under the current frozen Gate11H source, those missing components are:

- no explicit later-source marker
- no single later-source identity
- no explicit full-path attachment on that same later source

### 5.2 Minimum Same-Source Later-Source Instantiation Rule

The path counts as defined only if the rule requires one same later source carrying:

- one explicit `later_source_id` or `later_frozen_run_id`
- one later source and only one later source
- one declaration marker
- one candidate id
- one class
- one explicit host-failure sentence
- matched status, registry, and read surfaces

Those additions must stay on the same later source.

### 5.3 Anti-Shortcut Boundary

The path counts as defined only if it forbids reliance on:

- broader-settlement promotion
- retroactive rewrite
- graph-wide leap
- worker-side synthesis
