# Genealogy Benchmark Note

## Scope

This note applies only to the `genealogy` world within CFA-style evaluation.

It does not change:

- canonical CFA labels
- canonical `inside_span` evaluation
- Gate5 boundary
- Gate5 comparator

It records how `genealogy` should be read when `rotor_loop_chordal_v1` shows persistent prefix / onset sensitivity under the fixed FWHT baseline.

## Canonical Evaluation

The canonical `genealogy` benchmark view remains:

- token labels defined by the existing `inside_span`
- aggregate reporting on the same canonical labels used elsewhere in CFA

Canonical aggregates remain the source of record for:

- cross-world comparison
- branch promotion / demotion claims
- any statement about raw comparator standing

## Diagnostic Geometry View

The following geometries are diagnostic-only:

- `onset_only`
- `start_neighborhood_w1`
- `start_neighborhood_w3`
- `prefix_only_w1`
- `prefix_only_w3`
- `symmetric_dilation_k1`
- `symmetric_dilation_k3`

These views exist to answer a narrower question:

Is the persistent `genealogy` failure better explained by supervision geometry mismatch than by a dead or meaningless rotor signal?

They are not canonical replacement labels.

## Current Reading

Under the fixed FWHT baseline and fixed `rotor_loop_chordal_v1`:

- canonical `inside_span` remains negative on `genealogy`
- `prefix_only_w3` becomes positive on `genealogy`
- this supports a supervision-geometry mismatch reading

This is evidence about how to interpret `genealogy`, not permission to rewrite CFA labels.

## Reporting Rule

When `genealogy` is discussed in a Gate5-or-later report:

1. canonical `inside_span` results must be shown first
2. any diagnostic geometry result must be labeled `diagnostic-only`
3. canonical and diagnostic views must not be merged into one aggregate
4. diagnostic views may support interpretation, but not replace the canonical leaderboard
