## 6. Falsifiers

The falsifiers must be written before any Gate9B execution.

Gate9B weakens or fails under any of the following.

### 6.1 Cleaner-Cell Dominance

If the dominant holonomy read remains larger or less quiet on cleaner cells than on conflict cells, Gate9B does not earn explanatory status.

More sharply:

- if `clean_support` or `surface_noisy_clean` continue to dominate the main support-cycle holonomy read, the present motif family has not yet earned explanatory language

### 6.2 Direct-Contradiction Escape

If the only cell where holonomy seems to work is:

- `direct_contradiction`

then Gate9B is still too weak.

It must not win by retreating to the easiest conflict type.

### 6.3 Distributed-Incompatibility Failure

If `distributed_incompatibility` does not produce a materially more informative or more stable cycle read than cleaner cells, Gate9B has not yet reached its real proving ground.

### 6.4 Missing-Anchor Collapse

If the chosen motifs rely so heavily on missing anchors or missing cycle legs that conflict-side interpretability cannot be assessed, then the study fails as designed, even if the code runs correctly.

### 6.5 Scalar-Ranking Drift

If the work starts optimizing one scalar holonomy summary without preserving the explicit cycle and failure-surface view, Gate9B has regressed into score-first behavior.
