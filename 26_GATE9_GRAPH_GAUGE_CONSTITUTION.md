## 0. Why Gate9 Exists

Gate8 closed with an explicit outcome:

- standing survived retrieval conflict
- standing survived one controlled rendering-family shift
- a second controlled shift exposed a visible portability boundary
- the explanatory bridge remained unresolved

That means the next mainline cannot honestly be:

- one more rescue bridge
- one more scalar score
- one more threshold-shaped summary

The next mainline must change the first-class object.

Gate9 therefore begins from this sentence:

- pale-ale should move from scalar score comparison to graph-gauge constitution over local objects and transports

## 1. Identity

Gate9 is not a score extension.

Gate9 is:

- the first discrete graph-gauge constitution for pale-ale

Its job is not to produce a prettier scalar ranking first.

Its job is to define:

- what the local objects are
- what the transport law is
- what counts as gauge change
- what closes
- what fails to close

## 2. Mainline Shift

Gate9 changes the subject in three explicit ways.

### 2.1 8D Doctrine Steps Down

`8D` no longer acts as the mainline ontology.

It may remain only as:

- interchange legacy
- compatibility lane
- historical scaffold

The next mainline local object is not fixed 8D state.

It is:

- variable-rank local span / projector

### 2.2 Score-First Steps Down

Gate9 does not begin by asking:

- which scalar score wins

Gate9 begins by asking:

- what the local object is
- what transport means between local objects
- what invariant failure to close looks like on a graph

### 2.3 Field Urgency Steps Down

Field aggregation remains deferred.

Gate9 is not allowed to jump directly to:

- defect field ontology
- basin language as the primary public object

First:

- constitution
- connection
- closure

Later, if earned:

- field-like aggregation

## 3. Base Graph

Gate9 exits the token-chain-only viewpoint.

The first public base graph remains intentionally narrow.

### 3.1 Node Types

The Gate9A node ontology is:

- `token_state`
- `support_chunk`
- `conflict_chunk`
- `answer_state`

The following are explicitly deferred:

- `question_state`
- `retrieval_co_reference`
- richer discourse or graph motifs

### 3.2 Edge Types

The Gate9A edge ontology is:

- `temporal_transition`
- `support_anchor`
- `conflict_anchor`
- `answer_projection`
- `quietness_pair`

The purpose of this graph is not decorative richness.

It is:

- to make local gluing structure explicit
- to let anomaly appear as graph-local transport failure rather than as linear score fluctuation

## 4. Local Object

Each node `i` carries one local object:

- `O_i := (P_i, Sigma_i, r_i, M_i)`

where:

- `P_i` = local projector
- `Sigma_i` = local singular spectrum
- `r_i` = effective rank
- `M_i` = provenance, flags, and anchor metadata

The mainline primitive is:

- `P_i`

Basis vectors may exist computationally, but they are not the public primitive.

Reason:

- basis choice is gauge-jitter sensitive
- projector is the more stable object across harmless basis change

## 5. Gauge Law

Gate9 must define gauge before it tries to speak about curvature, sheaf structure, or spectral law.

The public gauge law is:

- basis change inside the same local span must not change court-level diagnostics
- projector is the gauge-invariant primitive
- basis may appear only as an auxiliary carrier for transport computation

The minimum gauge discipline is:

- same span, different basis choice -> same court-level observable
- same world, different surface realization -> explicit quietness relation, not hidden negative control

If this law is not explicit, the rest of Gate9 becomes metaphor.

## 6. Connection Law

Gate9 is not yet an affine geometry line.

The first connection is:

- discrete connection on variable-rank local spans

For each edge `(i, j)`, Gate9 defines a transport object:

- `T_ij`

The first public transport law is:

- equal-rank case: orthogonal transport on aligned local spans
- rank-mismatch case: partial isometry / Procrustes-type transport

Gate9 is explicitly not required yet to model:

- translation / origin shift as a first-class affine term
- full `GL(r)` transport
- nonassociative transport

The order is:

1. orthogonal / subspace connection
2. rank-aware partial isometry
3. affine lift only if later evidence requires it

The connection layer must also define:

- missing-edge enums
- undefined-anchor enums
- rank-failure enums
- transport fallback rules, if any

These failure states must be explicit rather than absorbed into scalar smoothing.

## 7. Primary Observables

Gate9 must avoid score-zoo drift.

The first public observables are only these three.

### 7.1 Edge Transport Defect

`D_ij`

This is the local mismatch that remains after transporting between adjacent local objects.

Its role is:

- local diagnostic
- edge-scale defect readout

### 7.2 Small-Cycle Holonomy

`W_C`

This is the loop residual on small, explicit cycles.

Gate9A does not allow implicit closure.

Holonomy is defined only when the cycle contains an explicit closing leg under the declared node/edge ontology.

That closing leg must be one of:

- an instantiated edge already present in the graph
- an explicitly allowed inverse transport of an instantiated anchor or projection edge

The first cycles should therefore stay simple and explicit, such as:

- `token_state -> support_chunk -> answer_state -> token_state` when the answer node carries an explicit return projection to the originating token
- `token_state -> conflict_chunk -> answer_state -> token_state` when the answer node carries an explicit return projection to the originating token
- `support_chunk -> answer_state -> quietness-paired answer_state -> support_chunk` when both answer nodes carry explicit support-anchor legs to the same support chunk

This is the first main readout for local non-closure.

### 7.3 Anchor-Conditioned Closure

This observable asks:

- after support- or conflict-conditioned anchoring, does the path still fail to close at the answer node

This is the Gate9 carry-forward object most likely to clarify:

- distributed incompatibility
- answer-side inconsistency after explicit anchoring

## 8. What Is Deferred

The following are real possibilities, but they are not Gate9A first-class obligations.

### 8.1 Connection Laplacian

Connection Laplacian structure is promising.

But it is not the public center of Gate9A.

It should appear only after:

- node/edge ontology is stable
- connection law is explicit
- small-cycle holonomy reads are already legible

So its natural home is:

- Gate9B or Gate9C

not Gate9A.

### 8.2 Sheaf / Cohomology Language

Gate9 should not lead with sheaf branding.

The correct order is:

- gauge first
- sheaf second

Only after local objects, edge transport, and loop inconsistency are already explicit can cover / section / cocycle language become more than metaphor.

### 8.3 Spectral Language

Gate9 should not lead with spectral branding either.

Spectral / Laplacian language becomes serious only after:

- connection law is fixed
- observables are stable

Physics language such as:

- `Berry`
- `Yang-Mills`

may remain as internal structural compass only.

They do not yet belong in the public Gate9 headline.

### 8.4 Nonassociative Line

Nonassociative or octonionic escalation remains out of the public Gate9 engine.

It may remain as:

- private north-star horizon

But the public Gate9 line stays:

- associative discrete gauge line

## 9. Gate9 Phase Order

Gate9 should be treated as one workstream with staged obligations.

### 9.1 Gate9A

Gate9A is:

- graph-gauge constitution on the existing Gate8 surfaces

Its job is to fix:

- node types
- edge types
- local object
- gauge law
- connection law
- edge defect / small-cycle holonomy / anchor-conditioned closure

Its question is:

- when the Gate8 court is lifted into graph + gauge form, does the standing phenomenon become more structurally legible without rescue operations

### 9.2 Gate9B

Gate9B is:

- focused small-cycle holonomy study

Its job is to compare a small number of cycle motifs under the same constitutional law.

It is not yet:

- graph-wide smoothing
- field aggregation

### 9.3 Gate9C

Gate9C is optional and conditional.

It begins only if Gate9A/B produce stable graph-gauge reads.

Its likely object is:

- connection-Laplacian-style inconsistency energy

But even there, the framing remains:

- gauge-aware inconsistency structure

not:

- full field ontology

## 10. Forbidden List

Gate9 must explicitly forbid the old failure modes.

The following are forbidden in the mainline constitution:

- reinstating fixed 8D doctrine as ontology
- score rescue by scalar shaping
- field aggregation as the opening move
- immediate sheaf branding
- immediate spectral branding
- immediate Yang-Mills branding
- immediate octonionic or nonassociative mainline
- benchmark-zoo expansion before the constitution stabilizes

## 11. Success And Failure

Gate9 succeeds if it does at least the following:

- defines a stable base graph
- defines a stable local object
- defines a usable connection law
- yields gauge-disciplined observables that make closure failure more natural than scalar comparison did

Gate9 fails if any of the following happens:

- node or edge ontology expands faster than the constitution can stay readable
- basis-dependent artifacts leak into public claims
- observables collapse into another scalar zoo
- bridge rhetoric returns without connection law actually being fixed
- high-level mathematical branding outruns the experimental object

## 12. Final Gate9 Sentence

The Gate9 mainline sentence is:

- move pale-ale from token-chain scalar comparison to graph-gauge local-object geometry

The shortest memory hook is:

- define the connection before speaking about the curvature
